# Android APK wrapper

The Android version bundles the same web app with Capacitor. It does not load
the hosted site, so its health records are not part of Chrome or another
browser's site-data partition.

## Build

Requirements:

- Node.js 22 or newer
- Android Studio / Android SDK 36
- Java 21 (Android Studio's bundled JBR works)

From the repository root:

```powershell
npm install
npm run android:apk
```

Output:

```text
android/app/build/outputs/apk/debug/app-debug.apk
```

`npm run android:sync` refreshes the bundled web assets without building. Do
not edit `www/` or `android/app/src/main/assets/public/` directly; both are
generated by the sync command.

## Storage and biometric design

- The `NativeSecure` Capacitor plugin stores serialized app values in private
  Android `SharedPreferences`. The cycle state remains encrypted by the web
  layer with PBKDF2 + AES-256-GCM before it reaches native storage.
- PIN hash and encrypted state changes use one atomic preference/IndexedDB
  transaction, preventing a failed PIN change from leaving mismatched keys.
- Optional biometric unlock encrypts the four-digit PIN with an auth-per-use
  AES-GCM key in Android Keystore. `BiometricPrompt` must authorize each
  decrypt operation with `BIOMETRIC_STRONG`.
- Adding or removing enrolled biometrics invalidates the Keystore credential;
  the user can still enter the PIN and enable biometric unlock again.
- Android backups and cleartext network traffic are disabled in the manifest.
  Uninstalling the APK or clearing its app data removes local records, so an
  encrypted file or Google Drive backup is still recommended.
- Changing the app PIN disables biometric unlock so the old device-bound
  credential cannot survive a credential rotation.
- Google Drive authorization uses Google Play Services rather than an embedded
  WebView. Short-lived access tokens remain in memory; the app stores only a
  local connected marker and asks Play Services for a fresh token when needed.

The sideload APK uses Android's automatically generated debug certificate so it
can be rebuilt without release-keystore setup, but its `debug` build type sets
`debuggable false`. Preserve the same local debug keystore for future updates;
changing the signing certificate requires uninstalling the old APK and removes
its app-private data unless the user exports a backup first.
